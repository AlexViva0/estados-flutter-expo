No crees el Future dentro de build

✗ Consulta en cada redibujo

Widget build(BuildContext context) {
  return FutureBuilder(
    future: obtenerEstudiantes(),
    // ↑ nueva petición cada vez
    builder: ...,
  );
}

✓ Créalo una vez en initState

late final Future<List<String>> _futuro;

@override
void initState() {
  super.initState();
  _futuro = obtenerEstudiantes();
}

build() puede ejecutarse muchas veces: al rotar la pantalla, al abrir el teclado o con cualquier setState. Si el Future se crea ahí, la API se consulta una y otra vez.

Día 2 · Bloque 5 · [Expositor 5]

Detalle que vale puntos con el docente: muchos ejemplos en internet (incluido el de nuestra investigación) llaman a la función dentro de build por simplicidad, pero la documentación oficial de FutureBuilder advierte que el Future debe obtenerse antes, por ejemplo en initState. Conectar con el bloque 2: initState se ejecuta una vez y build muchas. DEMO: poner un print dentro de obtenerEstudiantes(), abrir el teclado y mostrar en la consola cómo se repite.

5.2 · Riverpod

Provider, rediseñado

Expone datos y lógica con proveedores globales que no dependen del árbol de widgets. Trae soporte para datos asíncronos y facilita las pruebas.

final contadorProvider =
    NotifierProvider<Contador, int>(Contador.new);

class Contador extends Notifier<int> {
  @override
  int build() => 0;
  void sumar() => state++;
}

// en un ConsumerWidget:
final n = ref.watch(contadorProvider);

Ventajas

Ordena dependencias, maneja lo asíncrono y se prueba fácil.

Desventajas

Hay varios tipos de proveedor que aprender.

Día 2 · Bloque 4 · [Expositor 4]

Riverpod fue creado por el mismo autor de Provider para resolver sus límites: los proveedores se declaran como variables globales, no dependen del BuildContext y se detectan errores en compilación. En la interfaz se usa ref.watch para escuchar y ref.read para actuar, igual que en Provider. Ejemplo real: una app turística con un proveedor que consulta destinos desde una API y otro que guarda los filtros. La sintaxis cambia según la versión, así que siempre revisar la documentación de riverpod.dev.
